# 树与图：格式示例

这是 T050 的最小规范样稿，未经 T051 辅导效果评测，不是已上线的 Skill。

## 适用条件

适用例：用户正在检查两点连通性程序，希望理解一段遍历代码的表现。
不适用例：题目仅要求把若干整数相加，没有图或树的结构。
题目属于图类不代表必须使用某一种遍历算法；先看用户实际写了什么。

## 目标

依据本次材料给出可追溯的疑点，明确哪些判断仍缺证据，不判断用户是否完成 Goal。

## 所需输入

按[输入格式](schemas/input.schema.json)提供题目事实及出处、当前代码快照和已有公开运行证据。
runEvidence 可以为空；没有结果时明确尚未实测，不编造输入、运行记录或错误位置。
调用属于哪个 Goal/Subgoal，由外层 SkillInvocation 绑定，本文件不指定某个用户或某道题的编号。

## 处理方法

先核对提供的事实与代码是否适合图题分析，再按[检查参考](references/checks.md)审阅与当前代码有关的条件。
将可直接观察的代码行为与推测分开。只在有引用支持时指出疑点；材料不完整时列入未知项。
本示例只分析传入材料，requiredTools 为空。需要更多运行证据时报告缺项，不自行执行命令；后续系统提供工具时也要受统一权限约束。

## 禁止行为

不提供完整代码、完整题解或完整推导；不替用户指定题面没有要求的算法。
不修改 GoalState，不把本次分析或样例通过当作已验证进度。
不读取隐藏测试、Oracle 或无关数据，不把工具需求声明当作执行授权。

## 结果格式

按[输出格式](schemas/result.schema.json)返回 findings 和 unknowns。每个发现附上传入材料的引用编号。
findings 可以为空，不为凑齐字段制造错误。结构符合 Schema 不代表分析结论已被验证。
